# H&R 超时收容说明（订阅助手 Q 改版）

本文说明本插件在官方「订阅助手（增强版）」基础上新增的 **H&R 收容** 能力：什么时候收容、到期怎么算、什么时候删除、各配置项含义，以及与官方 H&R 助手插件的分工。

## 一句话概括

普通订阅种子的超时逻辑不变；**H&R 种子**如果超时仍未下载完成，不再直接删除，而是移入独立收容目录继续保种，等它做满站点要求的 H&R 时长后才清理。

## 适用范围

- 只处理 **H&R 种子**：普通种子仍按原有的「低进度超时删除」逻辑处理，不收容。
- 只处理 **订阅下载的种子**（插件下载任务记录里的种子）。
- 只处理 **超过门槛仍未完成** 的种子：能正常下完的 H&R 种子完全走正常流程（下载 → 整理入库 → 原目录继续做种），收容不介入。

## H&R 判定顺序

1. **下载器标签为主**：种子带 `H&R` 或 `HR` 标签即视为 H&R 种子（qb 读 tags，Transmission 读 labels）。
2. **站点名兜底**：标签缺失时，用下载历史里的站点名比对「站点H&R时长」名单，命中也视为 H&R 种子。

> 标签由 H&R 助手（Q 改版）每 5 分钟一轮巡检补写；只要该插件在运行，标签判据基本不会漏。

## 两个收容入口

| 入口 | 触发条件 | 说明 |
| :--- | :--- | :--- |
| 低进度超时 | 观察窗口内进度增长低于阈值、连续多次仍未恢复 | 官方原有超时判定的超时分支，改为收容 |
| 绝对时长收容 | 从加入下载起超过「收容门槛」仍未完成 | 本插件新增，慢速但持续下载的种子同样会被收容 |

收容门槛取「收容门槛（小时）」，留空时自动跟随「下载超时时间（分钟）/ 60」。

## 收容动作与善后

收容时把种子的保存目录移动到「收容目录」（默认 `/nastools/data/downloads/hr`，该目录不参与媒体库整理），随后：

- 登记收容记录：收容时间、站点、下载器、站点 H&R 时长、预估到期；
- 清理插件的下载任务记录与「下载中」待定状态；
- 归档删除指纹，避免同一发布被立刻重选；
- 按配置触发一次延迟补搜，让订阅去下别的资源；
- 发送「已收容」通知。

若收容链路失败（目录不可写、下载器不可用、移动失败），**保留种子不删除**，下一轮继续尝试，通知 6 小时限频一次。

## 到期与清理规则

站点 H&R 以 **下载完成** 为起算点，所以：

| 种子状态 | 处理 |
| :--- | :--- |
| 未下载完成 | 不按时间删。转入收容目录满「未完成清理天数」（默认 14 天）仍未完成时，按「站点不计 H&R」删除任务；是否连文件一起删跟随「到期删除源文件」配置（以收容时刻的配置为准） |
| 已下载完成 | 到期点 = **下载完成时间 + 站点 H&R 时长**，到点后在实际所在的下载器删除任务（含文件可选，同样以收容时刻的配置为准） |

完成时间来源：qBittorrent 取 `completion_on`，Transmission 取 `done_date`；取不到时回退此前观察到的完成时间，再回退收容时的预估到期。

> 为什么以「下载完成」起算：站点规则是从下载完成开始计时（例如「下载完成后 10 天内做种满 24 小时」），一直下不完的种子不会进入站点考察，所以删它不构成 H&R 违约；而如果种子在收容期间完成了，就应该从完成那一刻重新做满时长，否则会出现「刚下完就被删、只做了十几小时种」的违约风险。

## 站点 H&R 时长从哪里来

取值顺序（前者优先）：

1. **「站点H&R时长」配置里的站点值**（命中即用，不额外请求）
2. 种子标题 / 描述中写明的时长
3. 直连站点 H&R 页面抓取（`/myhr.php`、`/hr.php`、`/rules.php`，不走 MoviePilot 代理）
4. 默认值「默认H&R时长」（默认 168 小时）

自动抓取：每天 05:30 抓取一次并合并进配置（抓到的值比旧值小则保留旧值，避免提前删除）；也可执行命令 `/sub_hr_scan` 立即刷新。

人工核实过的站点值（截至 2026-09-10）：

| 站点 | 要求做种 | 考察期 |
| :--- | :--- | :--- |
| 彩虹岛 | 120 小时 | 按站点规则 |
| 52pt / 1PTBA | 24 小时 | 按站点规则 |
| CARPT | 24 小时 | 下载完成后 10 天内 |
| 库非 | 24 小时 | 下载完成后约 3 天内 |

## 配置项

| 配置项 | 默认 | 说明 |
| :--- | :--- | :--- |
| 超时收容（改为收容不删种） | 开 | 总开关；关闭后不再收容新种子（历史收容记录仍按到期清理） |
| 超时处理模式 | 收容 | 收容模式：H&R 种子超时转入收容目录（此时排除标签不生效）／排除标签模式：带排除标签的种子跳过处理，不执行收容 |
| 收容门槛（小时） | 跟随下载超时时间 | H&R 种子下载超过该时长仍未完成即收容 |
| 收容目录 | `/nastools/data/downloads/hr` | 收容种子移动到这里，不参与媒体库整理 |
| 到期删除源文件 | 开 | 到期（含未完成清理）时是否连文件一起删；修改后只影响之后新收容的种子，已在收容中的种子按收容时记录的值执行 |
| 未完成清理天数 | 14 | 收容后仍未下载完成满 N 天，按「站点不计 H&R」清理；0 表示不清理 |
| 默认H&R时长（小时） | 168 | 站点页面与种子信息都取不到时使用的兜底值 |
| 站点H&R时长 | 见上表 | 格式 `站点名:小时`，逗号或换行分隔；填了时长的站点同时视为 H&R 站点 |
| 自动刷新站点时长 | 开 | 每天 05:30 抓取各站 H&R 页面并合并 |

## 页面与日志

- **收容清单页**：插件详情页会列出当前收容中的种子，含站点、完成状态、需做种小时数、到期时间。
- **关键日志**：
  - `订阅收容：本轮检查 N 个未完成下载任务，超过门槛 X 个，其中 H&R 种子 Y 个`
  - `订阅收容：<种子> 已下载 X 小时仍未完成（门槛 N 小时），执行 H&R 收容`
  - `订阅收容：<种子> 非 H&R 种子，交回原超时删除逻辑`
  - `订阅收容到期：已在 <下载器> 删除 ...`
  - `订阅收容未完成清理：已在 <下载器> 删除 ...`
- **手动触发**：命令 `/sub_hr_scan`（立即刷新站点 H&R 时长）。

## 常见问题

**Q：为什么种子移到 /nastools/data/downloads/hr 后没有整理入库？**
A：收容目录刻意排除在媒体库整理范围之外，目的是保种、避免 H&R 违约。为此插件提供「收容往返」：
补搜再次命中同一份收容种子时，会把它从收容目录搬回它原来的影视下载目录继续下载，
下完后由正常流程整理入库；搬运只改保存目录，同一份种子不删除、不重新添加，做种不中断。
往返次数直接沿用「下载连续超时重试次数」：第 1 次收容进 HR，之后每命中一次在两个目录之间搬一次，
到达该次数的最后一轮时搬回影视目录并保留停手（不再自动搬动或删除）。

**Q：收容往返的判定顺序是什么？**
A：以「下载连续超时重试次数」= 3 为例：
1) 第 1 次超时（种子在影视目录）→ 收容进 HR 保种；
2) 第 2 次命中（种子在 HR）→ 搬回影视目录；下完即整理入库，若再超时则搬回 HR；
3) 第 3 次（最后一轮）→ 确保落在影视目录并保留停手，之后不再自动处理。
次数按订阅范围累计（电影整部、剧集按季与集号），不按时间窗口老化，因此配置几次就走几次。

**Q：为什么关闭了「收容」开关，收容目录里的种子还会被删？**
A：收容记录代表一次已承诺的保种，仍然会按到期时间清理；开关只影响是否收容新的种子。若要完全不管，请手动清理收容记录（重置数据会清空收容记录，但收容目录内的文件需自行处理）。

**Q：删收容目录的文件会不会把媒体库里的文件也删掉？**
A：媒体库采用硬链接时不会——删除源目录只是减少一个链接计数。但如果该内容尚未整理入库，删除即彻底删除，无法恢复。

**Q：站点抓不到 H&R 时长怎么办？**
A：直接把它写进「站点H&R时长」（例如 `CARPT:24`）。部分站点的规则页里做种时长所在段落不含 "H&R" 字样，自动抓取识别不到，人工维护更可靠。

**Q：和「H&R助手（Q改版）」是什么关系？**
A：分工如下——H&R 助手负责跟踪种子是否满足 H&R（打标签、算做种时间、达标摘标签）；本插件的收容负责把「下不完又必须保种」的种子安置到独立目录，等它满足站点要求后再清理。两者各自维护一份「站点H&R时长」配置。
